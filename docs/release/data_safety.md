# データセーフティ（Play Console）用の一覧

2026-11-16 時点のコード（`feature/store-prereg`）とリリース版の結合マニフェストを読んで作った。
Play Console の「データ セーフティ」フォームに入れる内容の下書き。最終的な判断はユーザーが行う。

## 結論（要点）

- **アプリ自身はどこにも通信しない**（自前のサーバー・解析ツール・クラッシュ収集は無い）。外に送るのは **AdMob（Google Mobile Ads SDK）だけ**。
- AdMob が集めて Google と共有するデータ：**IP アドレス（おおよその位置）・操作の記録（アプリの起動・広告のタップ・視聴）・診断情報・端末の ID（広告 ID・アプリセット ID）**。目的は広告・分析・不正防止。通信は TLS で暗号化。
- 位置情報の権限・連絡先・写真・アカウントなどは**使っていない**。ゲームのセーブは端末の中だけ（SQLCipher で暗号化、バックアップ対象外）。
- 「アカウントを作る」機能が無いので、「データ削除のリクエスト」の仕組みは不要（ただし Play は削除方法の説明を求めることがある。広告 ID は端末の設定でリセット・削除できる、と書ける）。

## 使っているライブラリと、外に送るデータ

| ライブラリ（版） | 何に使うか | 外への通信 | 送るデータ |
|---|---|---|---|
| Google Mobile Ads SDK `play-services-ads` 23.6.0 | リワード広告（雨乞い・コインのおまけ） | **あり**（Google の広告サーバー） | IP アドレス（おおよその位置）・操作の記録・診断情報・広告 ID／アプリセット ID（下の表） |
| Play In-App Review `review` 2.0.2 | レビューのお願い（Play ストアの小窓） | 端末の Play ストアのアプリを呼ぶだけ。アプリからは送らない | なし（Play ストアが Google の規約で扱う） |
| WorkManager 2.7.0 | 庭から離れているあいだの通知 | なし | なし |
| Room 2.8.4 ＋ SQLCipher 4.9.0 | セーブデータ（暗号化） | なし | なし |
| DataStore 1.1.1 | 設定（音量・通知など） | なし | なし |
| Media3 ExoPlayer 1.5.1 | BGM（アプリに入っている曲だけ再生） | なし | なし |
| Jetpack Compose・Hilt・Navigation・Lifecycle・kotlinx | 画面・しくみ | なし | なし |

### AdMob が集めるデータ（Google の公開資料「Play data disclosure」より）

| Play のフォームの分類 | 中身 | 収集 | 共有 | 目的 | 任意か |
|---|---|---|---|---|---|
| 位置情報 → おおよその位置 | IP アドレスから推定 | はい | はい | 広告・分析・不正防止 | 必須（広告を出す限り） |
| アプリのアクティビティ → アプリの操作 | アプリの起動・広告のタップ・視聴 | はい | はい | 広告・分析・不正防止 | 必須 |
| アプリの情報とパフォーマンス → クラッシュログ・診断・その他のパフォーマンスデータ | 起動時間・フリーズの割合・電池の使い方など | はい | はい | 分析・不正防止 | 必須 |
| デバイスまたはその他の ID | 広告 ID・アプリセット ID | はい | はい | 広告・分析・不正防止 | 必須 |

- 暗号化：すべて TLS（「データは転送時に暗号化される」→ はい）。
- 削除：広告 ID は端末の設定でリセット・削除できる。

## 通信をする場所（広告以外に送っているか）

| 場所 | 中身 | 判断 |
|---|---|---|
| `data/ads/RewardedAdManager.kt` | `MobileAds.initialize` と `RewardedAd.load`（`AdRequest` は既定のまま、追加の情報は付けない） | 唯一の通信 |
| `data/security/TrustedClock.kt` | `SystemClock.currentNetworkTimeClock()`：**OS が既に持っているネットワーク時刻を読むだけ**。アプリは通信しない | 送信なし |
| `ui/settings/StorePage.kt`・プライバシーポリシー | Play ストア／ブラウザを開くだけ（`ACTION_VIEW`） | 送信なし（開いた先のアプリの扱い） |
| `ui/settings/ContactMail.kt`（お問い合わせ） | 利用者のメールアプリに下書きを渡す。本文にアプリの版・機種名・Android の版が入る。**送るかどうかは利用者が決める** | アプリからの送信ではない。ただしメールを受け取れば、メールアドレスと機種名が開発者に届く（後述） |
| `ui/share/GardenShare.kt`（お庭をシェア） | 利用者が選んだアプリに庭の画像を渡す（`ACTION_SEND`、FileProvider） | 利用者の操作で他アプリへ渡すだけ |

結合マニフェスト（リリース）の権限：`INTERNET`・`ACCESS_NETWORK_STATE`・`AD_ID`・`ACCESS_ADSERVICES_AD_ID / ATTRIBUTION / TOPICS`・`WAKE_LOCK`・`FOREGROUND_SERVICE`（ここまで広告 SDK と WorkManager が足すもの）、`POST_NOTIFICATIONS`（アプリ）。位置・カメラ・連絡先・ストレージの権限は無い。

## 気をつけること（ユーザーの判断が要る）

1. **お問い合わせのメール**：Google の考え方では、利用者が自分でメールアプリから送るものは「アプリによる収集」に含めないのが一般的。ただし慎重にするなら「個人情報 → メールアドレス（任意・アプリの機能：サポート）」を足す。
2. **同意画面（UMP）が無い**：EU・英国などに配信するなら、AdMob の規約で同意のポップアップ（User Messaging Platform）が要る。日本だけで配信するなら当面は不要。配信国を決めてから。
3. **子ども向けにするか**：「対象年齢」に 13 歳未満を含めると、ファミリー向けポリシーで広告の設定（`setTagForChildDirectedTreatment` など）と認定広告ネットワークの扱いが必要。今のコードは設定していない。
4. **広告 ID**：`AD_ID` 権限が入っているので、Play Console の「広告 ID」の質問は「使用している（広告・分析）」と答える。
5. AdMob の資料は 2026-11 時点の最新版（SDK 25.5.0）の内容。アプリの 23.6.0 でも同じ分類だが、申告前に Google の「Play data disclosure」ページをもう一度見ておくとよい。

## フォームの答え（下書き）

- 必要なユーザーデータ タイプを収集または共有しますか：**はい**
- 収集するデータはすべて転送時に暗号化されますか：**はい**
- ユーザーがデータの削除をリクエストする方法を提供していますか：**いいえ**（アカウントが無い。広告 ID は端末の設定で削除できる）
- データ タイプ：上の AdMob の表の 4 つ（おおよその位置／アプリの操作／クラッシュログ・診断・その他のパフォーマンス データ／デバイスまたはその他の ID）。すべて「収集」「共有」、目的は「広告やマーケティング」「分析」「不正防止、セキュリティ、コンプライアンス」、処理は「必須」。
